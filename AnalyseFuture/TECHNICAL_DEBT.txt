TD-02 — ONE-FRAME CUT BOUNDARIES AND EXACT AUDIO TIMING
Priority: P0. Type: precision verification debt. Owner: core media + QA.

Paths: editor/apps/studio/e2e-web/main-editor-edit-export.spec.ts;
scripts/check_edit_content.py; tests/test_check_edit_content.py;
editor/packages/core/src/playback/; editor/packages/core/src/export/.

The current edited-export fixture uses 24fps and samples color near a one-second
cut at 0.94 and 1.04 seconds. Audio windows assert a minimum RMS, which proves
non-silent output in those ranges, not exact placement, phase, channel mapping or
speech fidelity. Extend known-time burst/silence and one-frame boundary fixtures;
include shifted-audio/wrong-cut negatives that independently fail. Add representative
frame rates/time bases and mixed audio rates. Do not weaken pixel/audio thresholds
merely to accommodate a failing output.
Gate: documented tolerances distinguish intended edits from one-frame and timed
audio regressions; compare preview and export with a defined sampling method.

Paths: editor/apps/web/src/services/auto-save.ts, project-manager.ts,
media-storage.ts; editor/packages/core/src/storage/project-serializer.ts;

Priority: P0 for a Windows release. Type: platform validation debt.
Owner: desktop/media/release engineers with Windows test hardware.

Paths: editor/apps/desktop/test/media-integration.test.ts;
editor/apps/desktop/test/export-integration.test.ts;

editor/apps/desktop/src/main/sidecar/export-job.ts;

The integration suites use describe.skipIf(!HAS_FFMPEG). HAS_FFMPEG checks the
platform binary under apps/desktop/resources/bin/<platform>-<arch>/, not merely

the earlier run therefore must not be counted as native media/export passes.
System FFmpeg supporting Python/browser tests does not qualify a Windows bundle.
Gate: trusted binary provenance/configuration, package/install/launch, real
import/edit/recover/export, cancellation, permissions and hardware fallback on
supported Windows environments. Signing and update behavior need their own gate.
